# T-2.3 — Implementar `GET/POST /boxes` y `PATCH /boxes/{id}`

| Campo | Valor |
|---|---|

| Cubre | RF-06, RNF-06 |
| Depende de | T-2.1 |

| Rama sugerida | `dev/fase-2-api` |
| Estado | pendiente |

## Objetivo

Listar, crear, renombrar y activar/desactivar boxes vía HTTP, según `docs/04-api.md`.

## Contexto

- ADR-006 (`PATCH`, boxes nunca se borran).
- `.ai-context/convenciones.md` (errores por capa, SQL parametrizado).

## Pasos de ejecución

1. **Repositorio** `api/src/repositorio/boxes.rs`:
   `listar(conn, incluir_inactivos)`, `obtener(conn, id)`, `crear(conn, nombre)`,
   `actualizar(conn, id, nombre: Option<&str>, activo: Option<bool>)`.
   Mapear `SQLITE_CONSTRAINT_UNIQUE` → `ErrorRepositorio::NombreDuplicado`.
2. **Servicio** `api/src/servicio.rs`: normalizar nombre (trim, 1..=40) → `ErrorServicio::DatosInvalidos`.
3. **HTTP** `api/src/http/handlers.rs`: `listar_boxes`, `crear_box` (201), `actualizar_box` (200).
4. Registrar rutas en `crear_router`.
5. Tests de integración en `api/tests/boxes.rs`.

## Patrones y buenas prácticas

- **Repositorio**: el handler nunca ve SQL. **Servicio** concentra reglas.
- `UPDATE` parcial: usar `COALESCE(?2, nombre)` en vez de construir SQL dinámico.
- Handler delgado: extraer → llamar servicio → devolver. Nada más.

## Validaciones

- [ ] V1 — `POST /boxes {"nombre":"Box 1"}` → 201 con `id`, `activo: true`.
- [ ] V2 — Repetir con `"box 1"` → 409 `nombre_duplicado`.
- [ ] V3 — `POST /boxes {"nombre":"   "}` → 400 `datos_invalidos`.
- [ ] V4 — `PATCH /boxes/1 {"activo":false}` → 200; `GET /boxes` ya no lo lista;
      `GET /boxes?incluir_inactivos=true` sí.
- [ ] V5 — `PATCH /boxes/999 {...}` → 404.
- [ ] V6 — `grep -rn "format!" api/src/repositorio` sin resultados que contengan SQL.
