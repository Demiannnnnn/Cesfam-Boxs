# T-2.9 — Respaldar la base al iniciar y rotar a 30 copias

| Campo | Valor |
|---|---|
| Fase | 2 — API |
| Cubre | RF-11 |
| Depende de | T-2.1, T-2.2 |
| Componente | api (`respaldo.rs`) |
| Rama sugerida | `dev/fase-2-api` |
| Estado | pendiente |

## Objetivo

Cada arranque crea `backups/gestion-box-AAAAMMDD-HHMMSS.db` y conserva solo los 30 más recientes.

## Contexto

- ADR-011 (`VACUUM INTO`).

## Pasos de ejecución

1. `pub fn respaldar(conn: &Connection, carpeta: &Path, ahora: NaiveDateTime) -> Result<PathBuf, ErrorRespaldo>`:
   `conn.execute("VACUUM INTO ?1", [ruta])` (parámetro, no concatenación). Si el nombre ya existe
   (dos arranques en el mismo segundo), agregar sufijo `-2`, `-3`…
2. `pub fn rotar(carpeta: &Path, conservar: usize) -> io::Result<usize>`: listar solo archivos que
   cumplan el patrón `gestion-box-*.db`, ordenar por nombre (el formato de fecha ordena
   cronológicamente) y borrar los más antiguos. Devolver cuántos borró.
3. Llamar en `main` **después** de migrar y **antes** de aceptar tráfico.
4. Si el respaldo falla, `error!` en el log pero **la API arranca igual** (disponibilidad > respaldo).

## Patrones y buenas prácticas

- Inyectar `ahora` como parámetro → tests deterministas.
- Nunca borrar archivos que no coincidan con el patrón (protege archivos puestos a mano).

## Validaciones

- [ ] V1 — Test: 35 llamadas a `respaldar` + `rotar(30)` dejan exactamente 30 archivos, los más recientes.
- [ ] V2 — Test: un archivo `otro.db` en la carpeta no se borra.
- [ ] V3 — El respaldo se abre con `sqlite3` y contiene las mismas filas que la base.
- [ ] V4 — Reiniciar la API 3 veces crea 3 respaldos.
