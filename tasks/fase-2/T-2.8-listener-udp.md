## Objetivo

Responder al broadcast `GESTIONBOX_BUSCAR` con `RespuestaDescubrimiento` para que las apps
encuentren al servidor aunque cambie su IP.

## Contexto

- Protocolo: `docs/04-api.md` § Protocolo de descubrimiento UDP.

## Pasos de ejecución

1. `pub fn iniciar(puerto: u16, info: RespuestaDescubrimiento) -> io::Result<JoinHandle<()>>`:
   `UdpSocket::bind(("0.0.0.0", puerto))` en `std::thread::spawn` con nombre `"descubrimiento-udp"`.
2. Bucle `recv_from` con búfer de 64 bytes; si el contenido es exactamente `MENSAJE_BUSQUEDA`,
   `send_to` del JSON al origen; si no, ignorar.
3. Errores de `recv_from`/`send_to` → `warn!` y continuar (nunca matar el hilo por un paquete).
4. Si el `bind` falla (puerto ocupado) → `error!` en log; la API HTTP **sigue funcionando**.
5. Separar la lógica pura `fn responder(datagrama: &[u8], info) -> Option<Vec<u8>>` para testearla.

## Patrones y buenas prácticas

- Hilo de SO (no tarea tokio) para aislar el descubrimiento del runtime HTTP, como pide el `.docx`.
- No responder a contenido desconocido: evita usar la API como amplificador.
