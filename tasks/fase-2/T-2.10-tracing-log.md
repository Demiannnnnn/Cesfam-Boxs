# T-2.10 — Configurar tracing hacia api.log

| Campo | Valor |
|---|---|
| Fase | 2 — API |
| Cubre | RNF-10 |
| Depende de | T-2.2 |
| Componente | api (`log.rs`) |
| Rama sugerida | `dev/fase-2-api` |
| Estado | pendiente |

## Objetivo

Todos los eventos y errores quedan en `<carpeta_datos>/api.log` con fecha, nivel y mensaje, y el
archivo no crece sin límite.

## Contexto

- ADR-012 (archivo fijo, rotación al arrancar si > 10 MB).

## Pasos de ejecución

1. `pub fn iniciar(ruta_log: &Path) -> Result<GuardiaLog, io::Error>`:
   - si `api.log` > 10 MB, renombrar a `api.anterior.log` (reemplazando el anterior);
   - abrir en modo *append*; `tracing_subscriber::fmt().with_writer(Mutex<File>)`, `with_ansi(false)`,
     filtro desde `RUST_LOG` con defecto `info`.
   - En modo debug, además escribir a stderr.
2. `std::panic::set_hook` que registre el panic con `error!` antes de terminar (NSSM lo reiniciará).
3. Capa `TraceLayer` de `tower-http` a nivel `debug` para peticiones (no inunda el log en `info`).
4. Eventos `info!` mínimos: arranque (versión, carpeta, puertos), respaldo creado, reserva creada,
   reserva cancelada, box creado/modificado, apagado.

## Validaciones

- [ ] V1 — Tras arrancar y crear una reserva, `api.log` contiene líneas `INFO` de arranque y de reserva.
- [ ] V2 — Test: con un `api.log` de 11 MB, `iniciar` lo renombra a `api.anterior.log`.
- [ ] V3 — El log no contiene códigos de color ANSI (`grep -P '\x1b\[' api.log` vacío).
