## Objetivo

La API guarda funcionarios y etiquetas (nombre + color) como entidades propias; boxes y
funcionarios pueden tener una etiqueta; las reservas se crean con `funcionario_id` de un
funcionario registrado y activo, en vez de un texto libre.

## Pasos de ejecución

1. `docs/02-requisitos.md`: agrega
   - RF-13 "Registrar funcionarios (agregar, renombrar, asignar etiqueta, desactivar); las
     reservas se asignan solo a funcionarios registrados y activos".
   - RF-14 "Definir etiquetas con nombre y color y asignarlas a boxes y funcionarios; la grilla
     muestra esos colores".
   - RF-15 "Buscar reservas (por funcionario, etiqueta o box en un rango de fechas) y boxes libres
     (por día, rango horario y etiqueta)" (lo implementa T-7.3).
2. `shared`:
   - Newtype `Color` en `shared/src/tipos.rs`: acepta `#RRGGBB` (hex, mayúsculas o minúsculas,
     se normaliza a minúsculas), serde como string, rechaza al deserializar lo demás. Tests.
   - En `modelo.rs`: `Etiqueta { id, nombre, color: Color, activo }`, `NuevaEtiqueta { nombre,
     color }`, `CambiosEtiqueta { nombre?, color?, activo? }`; `Funcionario { id, nombre,
     etiqueta_id: Option<i64>, activo }`, `NuevoFuncionario { nombre, etiqueta_id: Option<i64> }`,
     `CambiosFuncionario { nombre?, etiqueta_id?: Option<Option<i64>>, activo? }` (doble Option:
     ausente = no cambiar, `null` = quitar etiqueta; implementa el deserializador a mano con
     `#[serde(default, deserialize_with = ...)]`, sin crates nuevos). `BoxAtencion` gana
     `etiqueta_id: Option<i64>` (`#[serde(default)]`); `NuevoBox` gana `etiqueta_id`
     opcional; `CambiosBox` gana `etiqueta_id` con la misma doble Option.
   - `Reserva` gana `funcionario_id: Option<i64>` (`#[serde(default)]`); `funcionario: String`
     se mantiene (nombre resuelto). `NuevaReserva` y `NuevoLote` cambian `funcionario: String`
     por `funcionario_id: i64`.
   - `CodigoError`: agrega `funcionario_inactivo` y `etiqueta_inactiva` (422). Los nombres
     duplicados de funcionario y etiqueta usan `nombre_duplicado` con mensaje propio
     ("Ya existe un funcionario con ese nombre", "Ya existe una etiqueta con ese nombre").
3. Migración v3 en `db.rs` (una sola entrada nueva al final de `MIGRACIONES`), según ADR-017:
   tablas `etiqueta` y `funcionario`; `ALTER TABLE box ADD COLUMN etiqueta_id INTEGER REFERENCES
   etiqueta(id)`; `ALTER TABLE reserva ADD COLUMN funcionario_id INTEGER REFERENCES
   funcionario(id)`; `INSERT OR IGNORE INTO funcionario (nombre) SELECT DISTINCT trim(funcionario)
   FROM reserva`; `UPDATE reserva SET funcionario_id = (SELECT id FROM funcionario f WHERE f.nombre
   = trim(reserva.funcionario) COLLATE NOCASE)`; índice en `reserva(funcionario_id)`.
   Test: base en v2 con reservas de "Ana" y "ana " → tras migrar hay un solo funcionario y ambas
   reservas apuntan a él.
4. Repositorios nuevos `repositorio/etiquetas.rs` y `repositorio/funcionarios.rs` (listar con
   `incluir_inactivos`, crear, actualizar; orden por nombre). `repositorio/boxes.rs` lee/escribe
   `etiqueta_id`. `repositorio/reservas.rs`: todas las lecturas devuelven `funcionario` desde
   `LEFT JOIN funcionario` con `COALESCE(f.nombre, r.funcionario)`; al insertar escribe
   `funcionario_id` y también el nombre en la columna de texto.
5. Servicio: validar nombre de etiqueta (trim, 1..=40) y de funcionario (trim, 1..=80);
   `etiqueta_id` debe existir (404 "No se encontró la etiqueta") y estar activa (422) al asignarla;
   crear reservas/lotes exige funcionario existente (404 "No se encontró el funcionario") y activo
   (422 "Ese funcionario está desactivado"). Desactivar funcionario o etiqueta **no** borra ni
   modifica reservas existentes.
6. HTTP: `GET /etiquetas?incluir_inactivos=`, `POST /etiquetas`, `PATCH /etiquetas/{id}`;
   `GET /funcionarios?incluir_inactivos=` ahora devuelve `[Funcionario]` (activos por defecto,
   orden alfabético) — **reemplaza** la lista de nombres de ADR-016 (quita el código de "nombres
   recientes" si queda sin uso); `POST /funcionarios`, `PATCH /funcionarios/{id}`.
7. Tests de integración en `api/tests/` (nuevo `funcionarios.rs`, `etiquetas.rs`; adapta
   `reservas.rs` y el resto a `funcionario_id`): CRUD, duplicados sin distinguir mayúsculas,
   reserva con funcionario inexistente/inactivo, etiqueta inactiva al asignar, quitar etiqueta con
   `null`, renombrar funcionario cambia el nombre en las reservas ya hechas, color inválido → 400.
8. Ajusta `api/scripts/humo.sh` si usa `funcionario` en los cuerpos.
9. **No toques la app** (`app/`) salvo lo mínimo para que `cargo clippy --workspace --all-targets`
   y `cargo test --workspace` compilen si `app/src-tauri` usa los tipos de `shared` que cambiaron:
   en ese caso adapta solo las firmas en Rust (el frontend lo hace T-7.2).
10. Documentación: `.ai-context/contrato-api.md`, `docs/04-api.md`, `.ai-context/mapa-codigo.md`,
    estado de T-7.1 en `tasks/README.md` y
    `.ai-context/estado.md`.
