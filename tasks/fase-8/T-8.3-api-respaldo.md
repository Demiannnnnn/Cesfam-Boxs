# T-8.3 — API: entregar una copia consistente de la base

| Campo | Valor |

| Rama sugerida | `dev/fase-8-multiequipo` |
| Estado | pendiente |

## Objetivo

`GET /respaldo` devuelve un archivo SQLite completo y consistente de la base, aunque haya reservas
escribiéndose en ese momento.

## Contexto

- ADR-021. `api/src/respaldo.rs` ya respalda al arrancar (RF-11): reutilizar su forma de copiar.
- SQLite en WAL: no copiar el archivo a mano; usar la API de backup de `rusqlite`
  (`rusqlite::backup`) hacia un temporal en la carpeta de respaldos.

## Pasos de ejecución

1. `respaldo.rs`: función `copia_para_enviar(conn, carpeta) -> Result<PathBuf>` que hace el backup a
   un temporal único. Test: crear base con datos, copiar, abrir la copia y verificar filas e
   `PRAGMA integrity_check` = `ok`.
2. Handler `GET /respaldo`: corre la copia en `spawn_blocking`, responde 200 con
   `Content-Type: application/octet-stream`,
   `Content-Disposition: attachment; filename="gestion-box-AAAAMMDD-HHMMSS.db"` y el contenido. Borra
   el temporal al terminar, también si falla el envío. Error interno → 500 con mensaje en español.
3. Sin autenticación (ADR-020). Registrar en el log cada entrega con la IP del solicitante.
4. Test de integración del endpoint: el cuerpo empieza con `SQLite format 3\0` y se abre como base
   válida con las reservas creadas antes.
5. Documentar en `.ai-context/contrato-api.md` y `docs/04-api.md`.
