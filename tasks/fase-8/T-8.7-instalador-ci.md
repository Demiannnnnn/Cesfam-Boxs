# T-8.7 — Construir el instalador en GitHub Actions

| Campo | Valor |
|---|---|
| Fase | 8 — Varios equipos: modos, copia diaria y servidor de reemplazo |
| Cubre | RNF-12, RNF-13 |
| Depende de | T-8.2, T-8.6 |
| Componente | instalador, app |
| Rama sugerida | `dev/fase-8-instalador-ci` |
| Estado | pendiente |

## Objetivo

Un workflow de GitHub Actions, lanzado a mano, produce en Windows el `.msi` y el `setup.exe` de la
app con la API, NSSM y los `.bat` dentro, listos para instalar en el CESFAM sin compilar nada.

## Contexto

- Pedido del responsable (2026-11-06): el resultado final debe ser un ejecutable fácil de instalar en
  Windows. **Esto reemplaza la decisión de la fase 4 de no crear workflows.**
- ADR-018 (NSSM 2.24-101 con `AppNoConsole`), ADR-019 (CRT estático, `.cargo/config.toml`).
- T-4.4 (`app/src-tauri/tauri.conf.json`) y T-8.2 (carpeta `app/src-tauri/servidor/` de
  `bundle.resources`; los binarios no se versionan).
- Linux no puede generar el `.msi`: por eso se construye en `windows-latest`.

## Pasos de ejecución

1. `.github/workflows/instalador-windows.yml`, nombre `Instalador Windows`, disparado **solo** con
   `workflow_dispatch` (sin `push`, `pull_request` ni `schedule`), un job en `windows-latest`.
2. Toolchain Rust estable con target `x86_64-pc-windows-msvc` y Node LTS con caché de `npm`
   (`app/package-lock.json`).
3. `cargo build --release -p gestion-box-api` (toma el CRT estático de `.cargo/config.toml`).
4. Descargar `https://nssm.cc/ci/nssm-2.24-101-g897c7ad.zip` y verificar su SHA-256 fijado en el
   workflow: `99f5045fffbffb745d67fe3a065a953c4a3d9c253b868892d9b685b0ee7d07b8` (coincide con el
   `VERIFICATION.txt` del paquete `nssm` 2.24.101.20180116 de Chocolatey). Si no coincide, el job
   falla. Usar `win64\nssm.exe` del zip.
5. Copiar `target\release\gestion-box-api.exe`, `nssm.exe`, `instalador\instalar.bat` e
   `instalador\desinstalar.bat` a `app\src-tauri\servidor\` (la carpeta de recursos de T-8.2).
6. En `app/`: `npm ci` y `npm run tauri build -- --bundles msi,nsis`.
7. `tauri.conf.json`: `bundle.targets` pasa a `["msi", "nsis"]` y el instalador NSIS en español
   (`bundle.windows.nsis.languages: ["Spanish"]`). No cambiar el modo de WebView2 (T-0.7).
8. Subir como artefacto `instalador-windows` el `.msi` de `target/release/bundle/msi/` y el
   `*-setup.exe` de `target/release/bundle/nsis/`, con `if-no-files-found: error`.
9. Documentar en `instalador/README.md` y `docs/06-instalacion.md` cómo lanzar el workflow y dónde
   descargar el artefacto.

## Patrones y buenas prácticas

- Acciones oficiales con versión mayor fija (`actions/checkout@v4`, `actions/setup-node@v4`,
  `actions/upload-artifact@v4`); sin secretos, sin firma de código, sin releases ni tags.
- Rutas con comillas y `shell: pwsh` en los pasos de Windows.
- Ningún paso escribe fuera del checkout ni publica nada.

## Validaciones

- [ ] V1 — El YAML es válido y solo tiene `workflow_dispatch` (se revisa con un parser YAML).
- [ ] V2 — Cada ruta que el workflow lee existe en el repo o la crea un paso anterior; el nombre
      del artefacto es `instalador-windows`.
- [ ] V3 — `tauri.conf.json` sigue siendo JSON válido y `cargo test --workspace` pasa.
- [ ] V4 (GitHub, manual) — El responsable lanza el workflow y descarga el `.msi` y el `setup.exe`.
- [ ] V5 (Windows, manual) — Ambos instaladores instalan la app y el asistente instala el servidor.
- [ ] Definición de terminado general (`tasks/README.md`).
