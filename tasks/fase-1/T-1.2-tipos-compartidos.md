# T-1.2 — Definir en `shared` los structs Box y Reserva con serde

| Campo | Valor |

| Estado | pendiente |

## Objetivo

Tipos del dominio y del contrato HTTP/UDP en `shared`, serializables con serde y con
validación incorporada, usados por API y App.

## Contexto

- `.ai-context/contrato-api.md` (tipos exactos).
- ADR-009 (`BoxAtencion`).

## Pasos de ejecución

1. `shared/src/horario.rs`: constantes `HORA_INICIO = 8`, `MINUTOS_POR_BLOQUE = 30`,
   `CANTIDAD_BLOQUES = 24`; funciones `hora_inicio_bloque(Bloque) -> NaiveTime`,
   `etiqueta_bloque(Bloque) -> String` ("08:00").
2. `shared/src/tipos.rs`:
   - `Bloque(u8)` con `Bloque::new(u8) -> Result<Bloque, ErrorTipo>`; `Deserialize` vía
     `#[serde(try_from = "u8")]`, `Serialize` vía `into = "u8"`.
   - `Fecha(NaiveDate)` con `FromStr` (`%Y-%m-%d`), `Display`, serde como string.
3. `shared/src/modelo.rs`: `BoxAtencion`, `Reserva`, `NuevoBox`, `CambiosBox`, `NuevaReserva`,
   `EstadoSalud`, con `#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]`.
4. `shared/src/error.rs`: `CodigoError` (`snake_case`) y `ErrorRespuesta { codigo, mensaje }`;
   constante `MENSAJE_BLOQUE_OCUPADO = "Ese bloque acaba de ser tomado"`.
5. `shared/src/descubrimiento.rs`: `MENSAJE_BUSQUEDA = b"GESTIONBOX_BUSCAR"`,
   `RespuestaDescubrimiento`, `PUERTO_HTTP_POR_DEFECTO = 8000`, `PUERTO_UDP_POR_DEFECTO = 8001`.
6. `lib.rs` reexporta todo.
7. Tests unitarios: bloque 24 rechazado, `"2026-02-30"` rechazado, ida y vuelta JSON de `Reserva`,
   `etiqueta_bloque(0) == "08:00"`, `etiqueta_bloque(23) == "19:30"`.

## Patrones y buenas prácticas

- **Newtype + parsear, no validar**: un `Bloque` fuera de rango no puede construirse, así que
  el resto del código no vuelve a validar.
- Sin dependencias de red/DB en `shared` (mantenerlo liviano y testeable).
- `#[serde(deny_unknown_fields)]` en DTOs de entrada para detectar errores del cliente.
