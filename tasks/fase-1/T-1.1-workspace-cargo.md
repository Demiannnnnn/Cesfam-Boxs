# T-1.1 — Crear el workspace de Cargo con `api/`, `app/` y `shared/`

| Campo | Valor |
|---|---|
| Fase | 1 — Proyecto base |
| Cubre | RNF-05 |
| Depende de | — |
| Componente | raíz, api, shared, app |
| Rama sugerida | `dev/fase-1-proyecto-base` |
| Estado | completada (2026-10-01, rama `dev/fase-1-2-api`) |

## Objetivo

Un workspace de Cargo que compila tres crates: `gestion-box-shared` (lib), `gestion-box-api`
(bin + lib) y `gestion-box-app` (Tauri, en `app/src-tauri`), con dependencias declaradas una
sola vez en `[workspace.dependencies]`.

## Contexto

- `.ai-context/contexto-proyecto.md` (stack y workspace).
- ADR-009 (crate `shared`), RNF-05 (un ejecutable, SQLite embebido).

## Pasos de ejecución

1. `Cargo.toml` raíz:
   ```toml
   [workspace]
   resolver = "2"
   members = ["shared", "api", "app/src-tauri"]

   [workspace.package]
   version = "0.1.0"
   edition = "2021"
   rust-version = "1.80"

   [workspace.dependencies]
   serde = { version = "1", features = ["derive"] }
   rusqlite = { version = "0.40", features = ["bundled"] }
   # … resto del stack
   ```
2. `cargo new --lib shared --name gestion-box-shared`.
3. `cargo new api --name gestion-box-api`; agregar `src/lib.rs` para exponer módulos a los tests.
4. Crear la app Tauri en `app/` (ver T-3.x); mientras tanto, puede quedar fuera de `members`
   si aún no existe, pero al cerrar la fase 3 debe estar incluida.
5. `[profile.release]`: `lto = true`, `codegen-units = 1`, `strip = true`, `panic = "abort"` no
   (queremos que tokio pueda registrar panics en el log).
6. `.gitignore`: `target/`, `datos-dev/`, `app/node_modules/`, `app/dist/`.
7. `rust-toolchain.toml` **no** se fija (el sistema usa toolchain estable); documentar la
   versión mínima en `rust-version`.

## Notas de implementación

- `app/src-tauri` se agrega a `members` al iniciar la fase 3 (rama `dev/fase-3-app`).

## Patrones y buenas prácticas

- **Dependencias centralizadas** (`workspace = true` en cada crate) → una sola versión de cada librería.
- `rusqlite` con `bundled`: compila SQLite dentro del `.exe` (no requiere DLL).
- Evitar features por defecto innecesarias (`default-features = false` en `reqwest` con `rustls-tls`).

## Validaciones

- [x] V1 — `cargo build --workspace` termina sin errores.
- [x] V2 — `cargo tree -p gestion-box-api | grep libsqlite3-sys` muestra la feature `bundled`
      (`cargo tree -e features -p gestion-box-api | grep bundled`).
- [x] V3 — `cargo build -p gestion-box-api --release` produce **un solo** ejecutable en `target/release/`.
- [x] V4 — `git status` no muestra `target/` ni `node_modules/`.
