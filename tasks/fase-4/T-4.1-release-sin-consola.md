# T-4.1 — Compilar la API en release con `windows_subsystem = "windows"`

| Campo | Valor |
|---|---|
| Fase | 4 — Instalación |
| Cubre | RNF-02, RNF-05 |
| Depende de | T-2.11 |
| Componente | api (`main.rs`) |
| Rama sugerida | `dev/fase-4-instalacion` |
| Estado | pendiente |

## Objetivo

`gestion-box-api.exe` en release no abre ventana de consola.

## Pasos de ejecución

1. Primera línea de `api/src/main.rs`:
   `#![cfg_attr(all(windows, not(debug_assertions)), windows_subsystem = "windows")]`
2. Como no hay consola, todo error de arranque debe ir a `api.log` (inicializar el log lo antes
   posible) y, si ni el log puede abrirse, al Visor de eventos vía `eprintln!` capturado por NSSM
   (`AppStderr`).
3. Compilar en Windows: `cargo build -p gestion-box-api --release`; o en Linux con
   `cargo xwin build --target x86_64-pc-windows-msvc -p gestion-box-api --release`.
4. Agregar metadatos de versión al `.exe` (opcional: crate `winresource` en `build.rs`).

## Validaciones

- [ ] V1 — Doble clic en el `.exe` (Windows) no abre ventana y `http://localhost:8000/health` responde.
- [ ] V2 — `cargo build` en debug sí muestra consola (útil para desarrollar).
- [ ] V3 — El `.exe` no depende de DLLs fuera de Windows (`dumpbin /dependents` solo lista DLLs del sistema).
